Executable constraint factors: message passing and constraint execution

A visual explanation of the factorized repair model using the same notation as the message-passing specification: variable nodes \(v\in\mathcal{V}\), constraint factor nodes \(c\in\mathcal{C}\), role scopes \(\mathcal{P}(c),\mathcal{S}(c),\mathcal{O}(c)\), type-specific executors \(F_{t(c)}\), and pressure messages \(m_{c\rightarrow v,r}^{(k)}\).

The one-sentence version

A constraint factor node \(c\) is a learned executable subprogram: it reads role summaries from its scope, produces a factor state \(a_c^{(k)}\) and satisfaction logit \(\ell_c^{\mathrm{pre},(k)}\), and uses that state to send role-conditioned pressure back to variable nodes before edit decoding.

1. Mental model: \(\mathcal{V}\) nodes carry facts; \(\mathcal{C}\) nodes execute constraints

Base variable message passing

The graph contains variable nodes \(v\in\mathcal{V}\): entities, predicates, literals, and role-specific predicate occurrences. A GIN/GINE layer computes \(\tilde{h}_v^{(k+1)}\) from ordinary KG neighborhoods.

Backbone update
\[ \tilde{h}_v^{(k+1)} = \mathrm{GNN}_k\Big( h_v^{(k)}, \{(h_u^{(k)}, e_{u\to v}) : u \in \mathcal{N}(v)\} \Big). \]

Executable constraint factors

The same graph also contains constraint factor nodes \(c\in\mathcal{C}\). Each factor corresponds to one constraint instance and has a dense type id \(t(c)\in\{0,\ldots,|\mathcal{T}|-1\}\). Its scope is represented by typed factor-to-variable edges, not a fixed tuple.

Conceptual scope
\[ \mathrm{scope}(c) = \mathcal{P}(c)\cup\mathcal{S}(c)\cup\mathcal{O}(c). \]
Terminology. This document uses the current specification’s distinction between symbolic executors and neural executors: symbolic executors create per-factor labels offline; the GNN forward pass runs type-specific neural executors \(F_{t(c)}\) and pressure modules.

3. Factor scope roles: \(\mathcal{P}(c), \mathcal{S}(c), \mathcal{O}(c)\)

The current implementation does not store factor scope as one fixed-arity tuple. Graph construction adds typed factor-to-variable edges. For a factor \(c\), these edges define three role sets:

Predicate role

\[ \mathcal{P}(c) = \{v : c\rightarrow v \text{ has role predicate}\}. \]

Subject role

\[ \mathcal{S}(c) = \{v : c\rightarrow v \text{ has role subject}\}. \]

Object role

\[ \mathcal{O}(c) = \{v : c\rightarrow v \text{ has role object}\}. \]

The sets can be empty, singleton, or multi-node. This is why the model uses role summaries rather than assuming an ordered tuple like \((p,q,s)\). In particular, duplicated predicate nodes mean each statement occurrence can have its own predicate node.

\(\mathcal{R}_r(c)\) Role set for \(r\in\{P,S,O\}\) Lets one equation cover predicate, subject, and object roles.
\(\mathrm{scope}(c)\) \(\mathcal{P}(c)\cup\mathcal{S}(c)\cup\mathcal{O}(c)\) Defines which variable nodes can influence and receive pressure from the factor.

4. Factor execution: from role summaries to satisfaction logits

The paper-facing path is per_type_v1. For each role \(r\in\{P,S,O\}\), the model computes a mean summary:

Role summary
\[ \bar{h}_{c,r}^{(k)} = \frac{1}{\max(1,n_{c,r})} \sum_{v\in\mathcal{R}_r(c)} h_v^{(k)}, \qquad n_{c,r}=|\mathcal{R}_r(c)|. \]

If a role has no scoped variables, its summary is the zero vector and the count is zero. These summaries, the factor-node embedding, and the log-counts form the factor executor input:

Factor input
\[ \phi_c^{(k)} = \Big[ h_c^{(k)} \;\Vert\; \bar{h}_{c,P}^{(k)} \;\Vert\; \bar{h}_{c,S}^{(k)} \;\Vert\; \bar{h}_{c,O}^{(k)} \;\Vert\; \log(1+n_{c,P}) \;\Vert\; \log(1+n_{c,S}) \;\Vert\; \log(1+n_{c,O}) \Big] \in \mathbb{R}^{4d+3}. \]

Type-specific executor
\[ (a_c^{(k)},\ell_c^{\mathrm{pre},(k)}) = F_{t(c)}(\phi_c^{(k)}), \qquad \hat{s}_c^{\mathrm{pre},(k)} = \sigma(\ell_c^{\mathrm{pre},(k)}). \]

Here \(a_c^{(k)}\in\mathbb{R}^{d_f}\) is the learned factor state and \(\ell_c^{\mathrm{pre},(k)}\in\mathbb{R}\) is a pre-edit satisfaction logit. Positive logits predict satisfaction; negative logits predict violation.

Derived violation score
\[ \widehat{\mathrm{viol}}_c^{(k)} = 1-\hat{s}_c^{\mathrm{pre},(k)}. \]
Current implementation detail. A violation score can be derived from the pre-edit satisfaction probability, but the current per_type_v1 pressure path does not directly pass \(1-\hat{s}_c^{\mathrm{pre},(k)}\) into the pressure modules. It uses the learned factor state.

Post-gold satisfaction head

During training and evaluation with gold edit labels, the model embeds the six gold edit target ids for the graph containing factor \(c\). Let this mean edit embedding be \(e_y\). The post-gold head predicts whether the factor is satisfied after the historical edit.

Post-gold auxiliary head
\[ \ell_c^{\mathrm{post},(k)} = Q_{t(c)}(a_c^{(k)},e_y), \qquad \hat{s}_c^{\mathrm{post},(k)} = \sigma(\ell_c^{\mathrm{post},(k)}). \]

5. Constraint-to-variable feedback: factor pressure

In the pressure-enabled model, factor pressure is applied after each backbone message-passing layer. The backbone first produces \(\tilde{h}^{(k+1)}\). The factor executor is then rebuilt on those post-GNN states:

Re-execute factors after backbone update
\[ \tilde{\phi}_c^{(k+1)} = \Phi_c(\tilde{h}^{(k+1)}), \qquad (\tilde{a}_c^{(k+1)},\tilde{\ell}_c^{(k+1)}) = F_{t(c)}(\tilde{\phi}_c^{(k+1)}). \]

For a destination variable \(v\in\mathcal{R}_r(c)\), the pressure message is:

Role-conditioned pressure message
\[ m_{c\rightarrow v,r}^{(k)} = G_{t(c),r} \Big( \big[ \tilde{a}_c^{(k+1)} \;\Vert\; \tilde{h}_v^{(k+1)} \big] \Big), \qquad r\in\{P,S,O\}. \]

What \(G_{t(c),r}\) means

\(G_{t(c),r}\) is the general typed-pressure notation. Canonical A1 ties these weights across factor types while retaining separate role-conditioned modules. The per-type-pressure appendix control unties them by factor type.

What it is not

The pressure equation is not a hard-coded negative feedback vector such as \(-\alpha\cdot \mathrm{viol}_c\cdot h_v\). That expression is only an intuition, not the current paper-facing equation.

Incoming factor-pressure messages are averaged by pressure degree and added as a residual correction:

Aggregation and residual update
\[ p_v^{(k)} = \frac{1}{\max(1,d_v)} \sum_{(c,r):\,v\in\mathcal{R}_r(c)} m_{c\rightarrow v,r}^{(k)}, \qquad d_v = \sum_{(c,r)}\mathbf{1}\{v\in\mathcal{R}_r(c)\}. \] \[ h_v^{(k+1)} = \tilde{h}_v^{(k+1)} + \lambda p_v^{(k)}. \] 
for each GNN layer k:
    tilde_h = GNN_k(h, KG_edges)
    tilde_phi_c = Phi_c(tilde_h)
    tilde_a_c, tilde_ell_c = F_t(c)(tilde_phi_c)

    for each role r in {P,S,O}:
        m_c_to_v_r = G_t(c),r([tilde_a_c || tilde_h_v])

    p_v = mean incoming factor-pressure messages
    h = tilde_h + pressure_residual_scale * p_v

Multi-constraint interaction

A variable can receive pressure from multiple constraints. The implemented aggregation averages by pressure degree, so constraints can reinforce each other, compete, or produce mixed pressure signals through the learned message functions.

\[ p_v^{(k)} \propto \sum_{c:\,v\in\mathrm{scope}(c)} m_{c\rightarrow v}^{(k)}. \]

6. Decoder and repair behavior

After message passing and optional pressure injection, the model pools node states and predicts six edit-slot distributions. There is no explicit delete-focus rule inside the neural proposal model.

Graph pooling
\[ h_G = \mathrm{meanpool}_{v\in G}(h_v). \]
Six-slot edit prediction
\[ \hat{y} = \big( \hat{y}_{add,s}, \hat{y}_{add,p}, \hat{y}_{add,o}, \hat{y}_{del,s}, \hat{y}_{del,p}, \hat{y}_{del,o} \big). \]

Repair behavior emerges from ordinary edit imitation loss on ŷ, optional factor satisfaction losses, optional factor pressure, and optional candidate chooser or direct safety objectives.

7. How backpropagation trains neural executors to approximate symbolic labels

The current model does not execute hard-coded symbolic constraint checkers inside the GNN forward pass. Instead, symbolic executors produce labels offline, such as factor_satisfied_pre and factor_satisfied_post_gold. The model learns differentiable neural approximations by minimizing binary cross-entropy.

Edit imitation

Cross-entropy over the six edit slots trains the proposal model.

\[ L_{\mathrm{edit}} = \frac{1}{6}\sum_j \mathrm{CE}(\hat{y}_j,y_j). \]

Pre-edit factor supervision

\(\ell_c^{\mathrm{pre}}\) is trained against symbolic satisfaction on \(G^-\).

\[ L_{\mathrm{pre}} = \mathrm{BCEWithLogits} (\ell_c^{\mathrm{pre}},s_c^{\mathrm{pre}}). \]

Post-gold factor supervision

\(\ell_c^{\mathrm{post}}\) is trained against symbolic satisfaction after the historical edit.

\[ L_{\mathrm{post}} = \mathrm{BCEWithLogits} (\ell_c^{\mathrm{post}},s_c^{\mathrm{post}}). \]

Gradient intuition

For a factor satisfaction logit \(\ell\) and binary target \(s\), the BCE gradient is:

\[ \frac{\partial L}{\partial \ell} = \sigma(\ell)-s. \]

If the symbolic label says the factor is satisfied but the neural executor predicts low satisfaction, the gradient pushes the logit upward. If the symbolic label says violated but the neural executor predicts high satisfaction, the gradient pushes it downward.

Total training signal

loss_per_graph =
    L_edit
  + weight_pre       * mean_checkable(L_pre)
  + weight_post_gold * mean_checkable(L_post)

Two ways factors learn. Factor heads learn directly from symbolic satisfaction labels. Pressure modules learn mostly from downstream repair losses: if a pressure message helps produce the target edit or improves the auxiliary objective, backprop reinforces the corresponding parameters.

8. Legacy shared executor path, and why it is not the main equation

The code still supports factor_executor_impl=legacy_shared for ablations. That path differs from the current paper-facing per_type_v1 executor and should not be used as the main explanation of the architecture.

Legacy shared pre-head
\[ \ell_c^{\mathrm{pre}} = H\Big( \mathrm{Proj}(h_c) \;\Vert\; \tau_{t(c)} \Big). \]
Legacy pressure input intuition
\[ \big[ h_c \;\Vert\; h_v \;\Vert\; \rho_r \;\Vert\; u_c \;\Vert\; \tau_{t(c)} \big], \qquad u_c = \sigma(w^\top h_c). \]

This is retained for ablation behavior. The main current explanation should use role summaries \(\phi_c^{(k)}\), type-specific executors \(F_{t(c)}\), and role-conditioned pressure modules \(G_{t(c),r}\).

9. Common confusions

Are factor nodes symbolic rules?

No. Symbolic executors produce labels offline and symbolic candidate evaluation may be used at decision time. In the GNN forward pass, \(F_{t(c)}\), \(Q_{t(c)}\), and \(G_{t(c),r}\) are learned neural modules.

Why not represent scope as a fixed tuple?

The current implementation has variable-size role sets. For example, a factor can have multiple local predicate occurrences in \(\mathcal{P}(c)\) and different constraints require different subject/object role scopes. Mean summaries and log-counts preserve this variable-arity structure.

Does \(\widehat{\mathrm{viol}}_c^{(k)}\) directly drive pressure?

Not in the current per_type_v1 pressure path. A violation score can be derived as \(1-\hat{s}_c^{\mathrm{pre},(k)}\), but pressure uses the learned factor state \(\tilde{a}_c^{(k+1)}\) together with the destination embedding \(\tilde{h}_v^{(k+1)}\).

Why can secondary constraints have weak influence?

Because the primary edit-imitation objective rewards matching historical edit slots. Unless secondary no-regression is strongly enforced at decision time or through auxiliary objectives, pressure can be learned mostly for primary repair behavior and historical imitation.

What does “executable” mean here?

It means the factor node runs a learned neural subprogram during message passing: build \(\phi_c^{(k)}\), execute \(F_{t(c)}\), estimate satisfaction, and generate pressure through \(G_{t(c),r}\). It does not mean hard-coded Wikidata validators are inside the differentiable forward pass.
